# Architecture — `model-apps`

> Plugin v1.0.6 — single-skill plugin focused on generating Power Apps generative pages for model-driven apps.

## Executive summary

`model-apps` is the simplest functional plugin in the repo by file count. It exposes one user-facing skill (`/genpage`) that runs the full lifecycle — validate prerequisites, gather requirements, generate Dataverse types, produce a single-file React 17 + Fluent UI v9 component, deploy via PAC CLI — in one invocation. Browser verification of the deployed page is done via a Playwright MCP server registered in `.mcp.json`.

## Technology stack

| Category | Technology | Purpose |
|----------|-----------|---------|
| Authoring | Markdown SKILL.md + YAML frontmatter | Skill workflow + sample reference docs |
| Execution | Node.js (`launch-playwright-mcp.js` only) | Playwright launcher with browser detection |
| MCP — local | Playwright (via `scripts/launch-playwright-mcp.js`) | Browser-based runtime verification of deployed pages |
| External CLI | `pac` (Power Platform CLI) | `pac model genpage generate-types`, `pac model genpage` deploy |
| Downstream stack | React 17, TypeScript, Fluent UI v9 (`@fluentui/react-components`) | Generated page code |

**No `scripts/lib/`, no agents, no hooks, no tests, no validators.** This plugin is intentionally lean.

## Architecture pattern

**Single-session full-lifecycle workflow.** The `/genpage` skill alone covers all phases. There is no router, no sub-skill delegation, no agent spawning.

## Key concepts

### Generative pages (genux)

React 17 + TypeScript single-file components that run inside model-driven Power Apps. Each page is a single `.tsx` file with `export default GeneratedComponent`.

### DataAPI

`props.dataApi` provides typed CRUD operations against Dataverse tables. Uses `RuntimeTypes.ts` (generated by `pac model genpage generate-types`) for type safety. **Column names must be verified from the generated schema — never guessed.**

### RuntimeTypes

TypeScript type definitions generated from Dataverse metadata. Contains entity types, enum registrations, and the `GeneratedComponentProps` interface. Generated via PAC CLI before code generation.

## Data architecture

No persistent data owned by the plugin. Dataverse data is accessed at runtime via the generated `DataAPI`, scoped by the deployed page's app permissions.

## Component design constraints (enforced by the skill)

| Constraint | Rule |
|------------|------|
| Framework | React 17 + TypeScript only |
| UI library | Fluent UI V9 (`@fluentui/react-components`) exclusively |
| DatePicker | `@fluentui/react-datepicker-compat` |
| TimePicker | `@fluentui/react-timepicker-compat` |
| File architecture | Single `.tsx` file — components, utilities, styles all inline |
| Allowed external libraries | React, Fluent UI v9, approved Fluent icons, D3.js (charts only) — and nothing else |
| Responsive design | Flexbox + relative units. Never `100vh`/`100vw`. |
| Accessibility | WCAG AA, ARIA labels, keyboard navigation, semantic HTML |
| Completeness | No placeholders, TODOs, or ellipses in the final output |

The generated component must be production-deployable in one shot — no partial code, no scaffolding for the user to fill in.

## API design

The plugin consumes:

| Service | Surface |
|---------|---------|
| Power Platform | `pac model genpage` commands (CLI) |
| Dataverse | `DataAPI` (runtime, scoped by app permissions) |

## Development workflow

```bash
# Local development
claude --plugin-dir /path/to/plugins/model-apps

# Skill invocation
/genpage
```

No tests today. No validators. No CI workflow specific to this plugin.

## Deployment

The skill itself deploys the generated page via `pac model genpage`. The plugin is distributed via the marketplace (`/plugin install model-apps@power-platform-skills`).

## Testing strategy

| Layer | Tooling | Location |
|-------|---------|----------|
| Unit | (none today) | — |
| Eval | Eval framework | `evals/model-apps/genpage/evals.json` |
| Manual | Browser verification via Playwright MCP | After deploy, the skill navigates to the page and verifies render |

## Skill authoring constraints (from this plugin's AGENTS.md)

- Keep `SKILL.md` under 500 lines.
- Short, descriptive `name` field.
- Descriptions in third person ("Creates X" not "This skill guides you through creating X").
- Progressive disclosure: SKILL.md for workflow, `references/` for details.
- Inline links to references: `See [troubleshooting.md](../../references/troubleshooting.md)`.

## Open risks / debt

- **No script tests.** If `launch-playwright-mcp.js` gains complexity, follow the `power-pages` convention and add `node --test` coverage.
- **No CI workflow.** Changes to this plugin are not gated by CI beyond the marketplace-level checks (plugin name validation).
