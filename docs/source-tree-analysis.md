## Critical folders — what to scan when

| Folder | Why it matters | When to read it |
|--------|----------------|-----------------|
| `.claude-plugin/marketplace.json` | Authoritative list of active plugins. Must be updated alongside per-plugin `plugin.json` for any rename / add / remove. | Adding/renaming/removing a plugin |
| `plugins/<plugin>/.claude-plugin/plugin.json` | Per-plugin manifest (name, version, keywords). | Releasing a new version of one plugin |
| `plugins/<plugin>/skills/<skill>/SKILL.md` | Skill workflow — phase structure, allowed-tools, version-check, model. | Authoring or modifying a skill |
| `plugins/power-pages/scripts/lib/` | Shared deterministic helpers. **Grep here before writing new utilities.** | Anything that touches Dataverse / YAML / auth |
| `plugins/<plugin>/references/` | Cross-skill reference docs. Linked via `${CLAUDE_PLUGIN_ROOT}/references/...` from SKILL.md. | Skill authoring — never duplicate this content |
| `plugins/power-pages/hooks/hooks.json` | PostToolUse:Skill validator registration. | Adding a hook-validated skill |
| `shared/skills/<skill>/` | Cross-plugin shared skill workflows (currently only `report-issue`). | Modifying a shared skill — also update every per-plugin wrapper |
| `evals/<plugin>/<skill>/evals.json` | Eval test cases. Long-running; not part of `node --test`. | Validating behavioural correctness of a skill |
| `.github/workflows/` | CI enforcement (version-check, plugin names, script tests). | Adding new CI rules |
| `scripts/install.js` | What users actually run via `curl … \| node`. | Changing install behavior |

## Entry points

- **User-facing install:** `scripts/install.js` (via `curl` pipe) or `/plugin marketplace add microsoft/power-platform-skills`
- **Plugin discovery:** `.claude-plugin/marketplace.json` → `plugins/<name>/.claude-plugin/plugin.json`
- **Skill discovery:** `plugins/<name>/skills/<skill>/SKILL.md` — auto-discovered by Claude Code
- **MCP server registration:** `plugins/<name>/.mcp.json` — auto-loaded when plugin is enabled
- **Hook registration:** `plugins/<name>/hooks/hooks.json` — only `power-pages` uses this currently
- **CI gates:** `.github/workflows/*.yml`
- **Local plugin testing:** `claude --plugin-dir /path/to/plugins/<plugin-name>`
