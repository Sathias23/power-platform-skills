## 2026-05-21

- **Run created.** Intent: Create. Workspace: `prd-power-automate-plugin-2026-05-21/`.
- **Input:** `plugins/power-automate/PROPOSAL.md` (design proposal — not a PRD; mixes capability intent with implementation choices).
- **Note:** PRD scope is "the power-automate plugin as a marketplace plugin," not the power-platform-skills repo as a whole. Folder name overrides default `{project_name}` token for clarity.
- **Working mode:** Fast path. **Stakes:** Internal / team tool. **Other inputs:** PROPOSAL + outputs in `docs/` as needed.
- **Research finding — scope boundary (load-bearing).** `power-pages/add-cloud-flow` REGISTERS existing flows into a site (metadata + client wiring); it does NOT author them. The new plugin owns AUTHORING. Two-plugin split mirrors canvas-apps (author) ↔ power-pages (integrate).
- **Research finding — competitive landscape (load-bearing).** Flow Studio MCP already occupies "AI agent generates flows from scratch via MCP, ships to Claude Code/Copilot." Microsoft Copilot covers natural-language authoring inside the maker portal. Defensible angle for this plugin: **clone-existing + ALM-first + Microsoft-sanctioned surfaces (Web API + `pac solution`), open-source, repo-aligned**. Must be sharply named in the PRD's "why this exists."
- **Research finding — pain points.** Top recurring: expression authoring friction; no version control / diff; connection-reference fragility on env promotion; no code-first editing surface; trigger-condition authoring; debugging run-history blind spot; connector docs friction.
- **Research finding — NFR footguns.** Schema churn (v1→v2 desktop migration deprecated Oct 2024; March 2026 wave); conn-refs break on import without pre-binding; new flows land in state 0 (off) by default; personal MSA accounts deprecated Jul 2025; legacy/non-OpenAPI connectors not editable via Copilot (likely same for any clientdata editor); repack fragility (one bad char → import rejection); agent blind to runtime failures without runs API.
- **Convention finding — 5 UX & reliability pillars** (power-pages PLUGIN_DEVELOPMENT_GUIDE): engaging loading via upfront TaskCreate; standalone Verify phase; sub-agent architecture for complex multi-step; deterministic Node scripts; three-point approval (after discovery, after plan, before deploy). New plugin must honor these.
- **Decision — v1 audience.** Internal Data3 only. Calibrates PRD around the team's actual flow-authoring needs, not public marketplace rigor. Marketplace promotion is post-v1.
- **Decision — positioning wedge.** "Clone existing flow + edit + ALM-promote using Microsoft-sanctioned surfaces (Dataverse Web API + `pac solution`)." Differentiates from Flow Studio MCP (create-from-scratch) and Microsoft Copilot (maker-portal chat). Create-from-scratch is explicitly NOT v1.
- **Decision — v1 scope cut.** Configure + Edit existing + Deploy (in-place PATCH). Smallest cut that proves the wedge.
- **Decision — v1 explicit exclusions.** Create-from-template (stretch), cross-env solution-pack/import (stretch), connection-reference creation wizard (only if a v1 edit needs one), run-history/debugging surface, multi-trigger-family template catalog.
